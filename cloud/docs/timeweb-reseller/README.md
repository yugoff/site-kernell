# База знаний: Реселлерская интеграция Kernell Cloud × Timeweb Cloud

Эта папка — единый источник правды для разработчиков и AI-агентов, развивающих портал `cloud.kernell.ru` (каталог `cloud/`) в полноценную реселлерскую облачную платформу поверх API **Timeweb Cloud**.

> **Точка входа для любого агента:** перед проектированием новой фичи, тарифа, биллинга или интеграции с Timeweb прочитайте этот файл, затем нужный тематический документ и при необходимости проверьте точные поля JSON-схем в локальном снимке OpenAPI [`openapi-bundle.json`](./openapi-bundle.json).

## Главные факты (TL;DR)

1. **Единый мастер-аккаунт партнёра:** В публичном API Timeweb Cloud **нет** эндпоинтов создания субаккаунтов или клиентских суббиллингов. Timeweb создаёт партнёру отдельный реселлерский аккаунт и выдаёт Bearer JWT-токен (`TIMEWEB_TOKEN`).
2. **Вся мультитенантность и биллинг — на стороне Kernell Cloud:**
   - 14 типов ресурсов в Timeweb поддерживают привязку к `project_id` (`/api/v1/projects`) — создавайте отдельный проект Timeweb на каждого клиента/воркспейс Kernell.
   - Аккаунт-глобальные ресурсы (домены, персоны, почта, VPC, firewall-группы, плавающие IP, сетевые диски, SSH-ключи, образы, VCS-провайдеры) **не имеют `project_id`** — их владение нужно строго хранить в БД Kernell и никогда не отдавать клиентам общие списки напрямую из Timeweb API.
   - S3-пользователи (`GET /api/v1/storages/users`) — аккаунт-глобальные, но у каждого бакета есть собственные `access_key` и `secret_key` — клиентам можно отдавать только ключи конкретного бакета.
3. **Экономика реселлера (по данным `https://timeweb.cloud/partners/reseller`):**
   - Скидка на облачные сервисы — **до 45%** (15% при объёме 100k–500k ₽/мес, 20% при 500k–1.5M ₽/мес, до 45% от 1.5M ₽/мес; считается средняя месячная выручка за последние 90 дней).
   - На выделенные серверы скидка фиксированная — **15%** (объём учитывается в пороге облачной скидки).
   - Для регистрации и продаж на юрлицо/ИП/самозанятого заключается прямой договор с ООО «ТАЙМВЭБ.КЛАУД» (есть ЭДО).
4. **Что уже сделано в репозитории:**
   - Сейчас подключена только проверка доступности доменов (`POST /api/domains/check` → `GET /api/v1/tlds?is_published=true` + `GET /api/v1/check-domain/{fqdn}`).
   - Кабинет, заказы (`status: 'draft'`) и управление услугами работают только как витрина раннего доступа и изолированный демо-режим.

## Неизменные правила (Invariants) для всех агентов

1. **Никогда не утекает `TIMEWEB_TOKEN` и внутренние ключи:** все запросы к `https://api.timeweb.cloud` идут только из серверного кода (`server-only`, API Routes, фоновые воркеры).
2. **Никакого доверия к клиенту в вопросах владения и цены:**
   - Владение ресурсом проверяется только по БД Kernell (`user_id` / `workspace_id`), а не фактом существования `id` в Timeweb.
   - Цена для клиента всегда пересчитывается и фиксируется на сервере Kernell на момент оплаты; хранятся как `cost_price` (оценка закупки), так и `retail_price` (цена продажи).
3. **Никакого провижининга без оплаты / резерва:** в Timeweb создание ресурса (`POST`) сразу начинает тарифицироваться на мастер-аккаунте. Сначала — проверка баланса/оплата + идемпотентная транзакция, затем — вызов Timeweb API.
4. **Идемпотентность и асинхронность:** `POST` к Timeweb API обычно возвращает `201 Created` в состоянии `installing`/`creating`. Каждая операция должна иметь внутренний `idempotency_key` и обновляться через связку **вебхуки Timeweb + фоновый поллинг статусов**.
5. **Лимит API Timeweb:** не более **20 запросов/сек на один endpoint** (`429 Too Many Requests`). Каталоги (`presets`, `tlds`, `os`, `locations`) обязательно кешировать на сервере, а воркеры запускать через очередь с rate-limiter и backoff.
6. **Логирование `response_id`:** при любой ошибке от Timeweb сохранять `response_id` (UUIDv4), `status_code` и `error_code` в системный журнал для тикетов в поддержку Timeweb (не показывая сырые детали мастер-аккаунта конечному пользователю).
7. **152-ФЗ и чувствительные данные:** регистрация доменов (`.ru`/`.рф`) требует паспортных данных (`POST /api/v1/persons`), а серверы возвращают `root_pass` / `vnc_pass` / `secret_key`. Нельзя хранить их в открытом виде в логах и нельзя допускать утечки ПДн — требуется шифрование в БД и размещение БД в контуре 152-ФЗ РФ.

## Быстрый поиск по локальному OpenAPI (`openapi-bundle.json`)

```bash
# Найти все эндпоинты по ключевому слову
grep -i "domains" cloud/docs/timeweb-reseller/endpoints-index.txt

# Посмотреть полную схему и описание конкретного эндпоинта
python3 -c '
import json
b = json.load(open("cloud/docs/timeweb-reseller/openapi-bundle.json"))
print(json.dumps(b["paths"]["/api/v1/servers"]["post"], indent=2, ensure_ascii=False))
'

# Обновить локальный снимок спецификации (когда потребуется свежая версия)
curl -sL https://timeweb.cloud/api-docs-data/bundle.json -o cloud/docs/timeweb-reseller/openapi-bundle.json
```
