# 05. Поэтапный план внедрения (Roadmap)

Ниже — практическая последовательность шагов от текущего состояния (`cloud/` с проверкой доменов и демо-режимом) до полноценной реселлерской облачной платформы.

---

## Phase 0. Партнёрство, юридика и платежи (параллельно с Phase 1)

**Цель:** получить реселлерский аккаунт, договор и легальную возможность принимать деньги от клиентов.

1. Оставить заявку на `https://timeweb.cloud/partners/reseller`, подписать договор с ООО «ТАЙМВЭБ.КЛАУД» (по ЭДО).
2. Получить отдельный реселлерский аккаунт Timeweb Cloud и токен `TIMEWEB_TOKEN` с нужными правами и квотами.
3. Зафиксировать у персонального менеджера ответы по:
   - отображению партнёрской скидки в ценах API (`/presets/*`, `/tlds`, `/account/services/cost`),
   - исключениям из скидки (домены, лицензии, AI-пакеты),
   - предоплате/лимитам мастер-аккаунта и правилам регистрации доменов на клиентов.
4. Подготовить Оферту, Политику ПДн (152-ФЗ), подать/обновить уведомление в РКН, разместить продакшн-инфраструктуру `cloud.kernell.ru` в контуре 152-ФЗ РФ.
5. Выбрать и подключить платёжный шлюз (ЮKassa / Т-Касса / CloudPayments / СБП) + онлайн-кассу 54-ФЗ + генерацию счетов для ООО/ИП.

## Phase 1. Фундамент платформы и синхронизация каталога

**Цель:** построить единый серверный слой работы с Timeweb и перенести каталог из статичного `catalog.ts` в БД с живой синхронизацией.

- **Модуль `cloud/lib/timeweb/`:**
  - Типизированный HTTP-клиент с `Bearer TIMEWEB_TOKEN`, таймаутами, структурированной обработкой ошибок (`status_code`, `error_code`, `message`, `response_id`), ретраями на `429`/`502`/`503` и rate-limiter (не выше ~15–18 req/s на endpoint для запаса до лимита Timeweb 20 req/s).
  - Интеграция с `GET /api/v1/account/finances` и `GET /api/v1/account/status` (проверка здоровья и баланса мастер-аккаунта).
- **Расширение БД (планировать миграцию на PostgreSQL до запуска реальных оплат):**
  - `workspaces` (или расширение `users`): `tw_project_id`.
  - `provider_catalog_cache`: синхронизируемые тарифы, ОС, локации, зоны TLD (закупочная цена Timeweb + timestamp).
  - `pricing_rules`: правила наценки Kernell (`markup_percent`, `fixed_retail_price`, `category`, `provider_preset_id`).
  - `user_email_tokens`: подтверждение email и сброс пароля.
  - Шифрование секретов (AES-256-GCM) для ПДн (`domain_persons`) и учётных данных ресурсов (`service_credentials`).
- **Обязательные доработки auth:** подтверждение email + восстановление пароля (`forgot-password` / `reset-password`), аудит-лог.

## Phase 2. Биллинг, кошелёк, эквайринг и леджер

**Цель:** принимать реальные деньги, вести точный учёт баланса (в копейках) и не допускать провижининга без оплаты.

- Таблицы БД: `ledger_entries`, `payments` (транзакции эквайринга + чеки 54-ФЗ), `orders` (добавить `cost_price`, `retail_price`, `paid_at`, `provider_payload`, `error_message`), `subscriptions` (для продлеваемых услуг: дата следующего списания, `auto_renew`, `suspended_at`, `grace_until`).
- API и UI пополнения баланса в разделе «Финансы» + webhook-обработчик платежного шлюза (идемпотентность, проверка подписи, фискализация).
- Биллинг-воркер (cron / queue):
  - уведомления о скором списании,
  - автоматическое списание продлений с кошелька,
  - остановка (`shutdown`/`pause`) и статус `suspended` при нехватке средств,
  - удаление в Timeweb по истечении grace-периода.
- Монитор мастер-баланса Timeweb (`/api/v1/account/finances`): алерты админу при `hours_left < 72`.

## Phase 3. Первые реальные продажи: Домены + Облачные VPS

**Цель:** заменить текущие заглушки (`draft` orders и `503` в управлении услугами) на реальную покупку и управление двумя базовыми продуктами из витрины.

### 3.1. Домены (полный цикл)
- Расширить `GET /api/v1/tlds` + каталог цен на странице `/domains` и в кабинете (регистрация + продление + трансфер, поддержка не только 4 зон, но всех опубликованных зон из `tlds` согласно `pricing_rules`).
- Форма и зашифрованное хранение **профиля администратора домена (`domain_persons`)** для физлица / ИП / ООО → синхронизация с `POST/PUT /api/v1/persons` (получение `tw_person_id`).
- Реальная покупка домена после оплаты:
  1. Проверка доступности (`GET /api/v1/check-domain/{fqdn}`).
  2. Создание заявки `POST /api/v1/domains-requests` (`register` / `prolong` / `transfer`).
  3. Оплата заявки `PATCH /api/v1/domains-requests/{request_id}` (`money_source: "use"`).
  4. Поллинг статуса заявки до `paid`.
- Реальное управление в кабинете:
  - Смена NS-серверов (`GET/PUT /api/v1/domains/{fqdn}/name-servers`).
  - Редактор DNS-записей (`GET/POST/PATCH/DELETE /api/v2/domains/{fqdn}/dns-records`).
  - Управление автопродлением (`PATCH /api/v1/domains/{fqdn}`) и продление в 1 клик.

### 3.2. Облачные серверы (VDS / VPS)
- Живой каталог на `/vps` и в кабинете из `/api/v1/presets/servers`, `/api/v1/configurator/servers`, `/api/v1/os/servers`, `/api/v1/software/servers`, `/api/v2/locations` (включая зарубежные локации `nl-1`, `de-1`, `pl-1`, `kz-1`, `us-4`, кастомный конфигуратор, DDoS L3/L4, пропускную способность, ПО маркетплейса).
- Подготовка `tw_project_id` клиента (`POST /api/v1/projects`), при необходимости загрузка SSH-ключей (`/api/v1/ssh-keys` с хранением владения в БД Kernell).
- Реальное создание сервера (`POST /api/v1/servers` с `project_id`), постановка задачи на ожидание готовности (`status === "on"`), сохранение IP и зашифрованного `root_pass` / `vnc_pass`.
- Реальное управление в кабинете:
  - `start`, `shutdown`, `hard-shutdown`, `reboot`, `hard-reboot`, `reset-password`, переустановка ОС (`action: "install"`), удаление.
  - Диски, бэкапы дисков и автобэкапы, снапшоты (`restore-points`), графики нагрузки (`/statistics`), дополнительные IP и PTR.
- Обработчик вебхуков Timeweb (`POST /api/webhooks/timeweb`) + фоновый поллер переходных статусов.

## Phase 4. Расширение облачной инфраструктуры

**Цель:** подключить востребованные инфраструктурные сервисы с привязкой к проектам и строгим контролем владения.

1. **Облачные базы данных (DBaaS):** PostgreSQL, MySQL, Valkey, MongoDB, ClickHouse, OpenSearch, Kafka, RabbitMQ (`/api/v1/databases`, `/admins`, `/instances`, `/v2/backups`, управление питанием).
2. **Объектное хранилище S3:** создание бакетов (`/api/v1/storages/buckets` с `project_id`), показ клиенту только его `hostname`, `access_key`, `secret_key` (строго без `/storages/users`!), настройка `website_config`, кастомных доменов и SSL.
3. **Managed Kubernetes:** выбор версии и CNI, создание кластера и групп нод, масштабирование, скачивание `kubeconfig`, аддоны.
4. **Сети и диски:** Балансировщики (`/balancers`), Firewall-группы (`/firewall/groups` с таблицей владения), Приватные сети (`/api/v2/vpcs` с таблицей владения), Плавающие IP (`/floating-ips`), Роутеры (`/routers`), Сетевые диски (`/network-drives`).
5. **CDN и Корпоративная почта:** CDN-ресурсы + Let's Encrypt сертификаты (`/api/v1/cdn/*`) и почтовые ящики на доменах клиента (`/api/v2/mail/*`).

## Phase 5. PaaS, Dedicated, AI-платформа и B2B-зрелость

**Цель:** закрыть всю линейку API («продавать всё») и масштабировать продажи.

1. **Apps Platform (`/api/v2/apps`) и Container Registry (`/api/v1/container-registry`):** деплой из Docker-образа или Git-провайдера, env-переменные, логи, управление. *(Обратить внимание на изоляцию `vcs-provider` — привязывать Git-токены строго к конкретному клиенту или поддерживать только публичные репозитории / Docker Registry).*
2. **Выделенные серверы (`/api/v1/dedicated-servers`):** каталог, проверка `autoinstall_ready`, поддержка периодов `P1M/P3M/P6M/P1Y`, ручная/инженерная очередь выдачи, отображение IPMI и IP.
3. **Линейка AI (`cloud-ai`):**
   - **AI Gateway:** перепродажа доступа к LLM через персональные `ai-keys`, контроль лимитов (`entity-limits`) и биллинг по статистике токенов (`statistic/token-usage`) с наценкой.
   - **AI-агенты, Базы знаний (RAG), Навыки/MCP, Боты (Telegram/MAX/Jivo/Crisp) и AI-решения.**
4. **Продукты вне API (заявочный контур):** витринные страницы с формой заявки в поддержку/менеджеру для VMware, VDI, L7 DDoS/WAF, серверов с аттестацией 152-ФЗ и 1С.
5. **Операционная зрелость:** система тикетов внутри кабинета, админ-панель (сверка с Timeweb `services/cost`, ручные возвраты, блокировка злоупотреблений/абузов), B2B-счета и ЭДО.
